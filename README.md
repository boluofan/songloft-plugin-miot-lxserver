# songloft-plugin-miot-plus

**基于 [上游项目 songloft-plugin-miot](https://github.com/songloft-org/songloft-plugin-miot) 的个人定制版**：原生内置 lxserver 在线搜索源，并针对语音点歌、歌手匹配、命中入库与发版流程做了定制。

设备分组、定时任务、语音/AI 对话、高级语音衔接、Lynx 前端等**通用能力与上游一致**，本页不再重复，详见[上游 README](https://github.com/songloft-org/songloft-plugin-miot#readme)。[English](README.en.md)。

> ™️ **商标声明**：本文中提到的 "MIoT" "MiHome" 等协议 / 产品名称均归各自商标权人所有，相关名称的出现仅出于互操作和指示性合理使用目的。本插件**未获得任何商标持有人的授权或背书**，与上述商标持有人**无任何关联**。

## 与上游的差异

| 能力 | 上游项目 | 本定制版 |
| --- | --- | --- |
| 在线搜索 | 依赖用户配置的外部 topone 源 | **原生内置 lxserver**，搜索与直链解析在插件进程内完成，无需额外中转插件；外部 topone 源保留作兜底 |
| 音源 | — | 内置 kw / kg / tx / wy / mg 五源，可启停、可调搜索优先级 |
| 歌手口令 | 常规本地匹配 | **索引扫描 + 宿主名录取并集**：导入的 remote 歌曲不在 `song_artists` 关联表里，宿主接口查不到，必须靠索引链路兜住 |
| 歌手在线歌曲 | 仅 top-1 单曲 | 可整队播放，临播前懒解析直链；临时队列，不入库 |
| 榜单点播 | — | 按榜单名动态匹配，整队播放，不写死榜单 id |
| 命中入库 | 曲库存直链 | 可选**引用入库**：只存「怎么取到这首歌」，播放时由宿主回调 `POST /api/music/url` 现解析，签名过期不失效 |
| 直推模式 | — | 可选直链不入库直接推流，直链带 5 分钟 TTL，过期临播前重解析 |
| 口令解析顺序 | 本地规则口令优先，AI 兜底 | 固定控制与点歌记忆仍本地优先；**搜索类口令 AI 优先、本地兜底**，AI 连续失败自动熔断；音量口令交回设备端处理 |
| 发版 | push main 自动发版，日期/序号版本 | **tag 驱动**，semver 与 tag 一致（`1.1.0` ↔ `v1.1.0`），版本由本分支自行推进 |

## 内置 lxserver 在线搜索

语音点歌在本地曲库未命中时发起在线搜索：内置 lxserver 与用户配置的外部 topone 源共同参与，未命中或失败时自动回退。搜索与直链解析都在插件进程内完成。

### 口令解析顺序（定制）

处理一条语音指令的先后顺序：

1. **固定控制**（停止、播放模式、收藏、定时、跳播等）——本地规则，命中即执行；
2. **点歌记忆**——命中历史成功点歌即结束，省掉一次解析；
3. **AI 口令解析**——需启用且未熔断，返回 `confidence !== 'low'` 且 `action !== 'unknown'` 才执行；
4. **本地搜索口令**——点歌 / 歌手 / 榜单 / 歌单，作为 AI 低置信度、未识别或失败时的兜底；
5. 仍未命中则转 AI 对话 / 语音恢复。

AI 连续解析失败 3 次会冷却 60 秒，期间直接走本地，避免每条指令都先等一次超时。**音量口令（大声 / 小声 / 调到 X）插件不再处理，由音响端原生完成**；定时任务里的音量动作、网页音量条等显式控制仍保留。

### 「播放歌手 X」的本地匹配（定制）

判断本地有没有这位歌手，会**合并两条链路的结果**，两条都拿不到歌才去在线搜索：

1. **索引扫描（基础，必跑）**：扫描歌单歌曲缓存 + 全曲库内存索引，不属于任何歌单的独立导入歌曲也能命中。这一步不能省——宿主把歌手存进 `song_artists` 关联表，而 `POST /songs/remote` 只写 `songs` 表，插件导入的 remote 歌曲不在关联表里，下面的宿主接口看不到它们。
2. **曲库名录 + 精确取歌（增量补充，宿主 ≥ 2.10.0）**：`GET /api/v1/songs/names?field=artist&exclude_playlist_labels=none&type=local,remote` 取全部去重歌手名（进程内缓存 10 分钟），用与索引搜索相同的归一化（繁简折叠、去标点）和模糊打分匹配，再 `GET /api/v1/songs?artist=<名>&exclude_playlist_labels=none` 一次取回这些歌。名录里的歌手名已拆成单个歌手，精确取歌按归一键命中对唱歌曲。显式限定 `type=local,remote` 是因为电台歌手取回来也会被跳过（无播放地址），只会白占候选名额。

两条链路按歌曲 id 去重合并（索引结果在前，保持「歌单内 → 独立导入」的顺序）。老宿主没有名录接口（404/400）、名录没匹配到或取歌返回空时，自然退化为只有索引扫描。

### 配置

入口：插件页 → 设置 → 语音 → **内置 lxserver 音源**。

- **启用开关**：打开后参与在线搜索（默认关闭）。
- **服务地址**：如 `https://lx.example.com:9527`。
- **用户 Token**：可选（`lx_tk_...`）。插件调用 `/api/user/auth/verify` 反查用户名，以 `x-user-name` + `x-user-token` 成对鉴权；留空则匿名，仅公开音源可用。
- **默认音质**：`320k`（默认）/ `flac` / `128k`；直链解析按 `flac → 320k → 128k` 阶梯降级。
- **音质降级**（默认开启）：关闭后只请求选定音质，不再向低音质回退。
- **搜索音源**：kw / kg / tx / wy / mg 可多选（至少保留一个），箭头调整顺序——顺序即搜索优先级，同一首歌多源都有时靠前的优先；并发搜索按匹配度排序去重。**仅 tx / wy 支持歌手检索**，其余音源会跳过。
- **搜索超时**：1 到 30 秒（默认 6 秒）；**直链超时**：3 到 60 秒（默认 12 秒）。
- **歌手在线歌曲**（默认关闭）：本地曲库没有该歌手时，用 lxserver 拉该歌手多首热门歌整队播放，而不是只播 top-1。仅 tx / wy 支持歌手检索；解析不出直链时退回 top-1 单曲。队列不入库，只有前 2 首在起播前解析，其余临播前解析，避免串行解析拖慢首播。
- **榜单播放**：说「播放热歌榜」「播放榜单飙升榜」等，从服务端榜单拉整队曲目。榜单目录按 `name` 动态匹配（精确名优先、同分按音源顺序），不写死榜单 id，服务端增减榜单无需改插件。五源都支持。队列形态与歌手在线歌曲一致；找不到榜单或首批解析失败会给 TTS 提示。

兼容搜索响应的两种形态（旧版裸数组、v2.1.3+ 的 `{list,...}` 对象），字段映射与兜底集中在 `src/lxserver/provider.ts` 适配层。

### 两个测试入口

- **测试连接**（内置源卡片内）：只验证服务地址与 Token 是否可用（探活 + token 反查用户名）。
- **在线搜索测试**：走与语音点歌**完全相同**的搜索链路，输出标明命中来源（`内置 lxserver` / `外部 topone`），可直接确认当前走哪条路。

### 在线搜索通用设置

搜索优先级、歌曲匹配阈值、超时、**直链不入库直接播放**、自动追加歌单对内置与外部源同时生效。

- **直链不入库直接播放**（默认关闭）：开启后带 http(s) 直链的结果不写入曲库，直接推给音箱，适合会过期的临时 CDN 直链。此时「自动追加歌单」整组隐藏。该模式下直链由插件当场向音源取，不经过宿主解析回调；只有音箱解不了源格式（webm/opus/flac/m4a 等）时才借宿主的 `/api/v1/proxy/transcode` 实时转 mp3。队列里的直链缓存 5 分钟过期，过期后临播时重解析。
- 关闭时，**命中以「引用」入库（解析型音源）**：库里只存「怎么取到这首歌」，不存直链；播放时宿主回调本插件的 `POST /api/music/url` 现解析。曲库条目不会因签名过期失效，可收藏、可重播，`dedup_key` 保证同一首只占一行；首次播放多一次解析往返（约 0.3~1s）。
  - 内置 lxserver：引用记 `平台 + 曲目标识`，按 id 重取直链。
  - 外部 topone 源：外部源通常只有搜索接口，引用记**当时怎么搜到的**（源 id + 关键词 + 曲名/歌手/时长提示），播放时重搜；原源缺失或失败时按配置顺序用其它启用源兜底。

## 播放历史（定制）

音箱侧播放在设备确认发声后上报宿主：真歌单按歌单 id、歌手口令按名录命中的规范署名落库；「全部歌曲」虚拟歌单只发事件不落库。详见[播放历史上报](docs/play-history-report.md)。

## 发版节奏（与上游不同）

发版由 **tag 驱动**，版本是与 tag 一致的 semver（`1.1.0` ↔ `v1.1.0`），默认 patch 自增；分支推送不发包。流程与进位规则见[发布](docs/releases.md)。
