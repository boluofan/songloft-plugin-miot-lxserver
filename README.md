# songloft-jsplugin-miot

A Songloft JS plugin generated by `create-songloft-plugin`. [English](README.en.md).

通过 MIoT 协议把歌曲投放到智能音箱设备的示例插件。

## Development

```bash
npm install
npm run dev         # watch + auto-upload to local Songloft
npm run build       # produce dist/miot.jsplugin.zip
npm run validate    # verify plugin.json hashes
```

### Lynx 前端

前端参考 bili 插件，使用 ReactLynx 原生元素与 `@songloft/lynx-plugin-sdk`，同时输出 `main.lynx.bundle`、`main.web.bundle` 和自动生成的 HTML 回退入口。保留歌曲列表、迷你/完整播放器以及设备、播放、语音、AI、定时、工具箱六类设置。

业务状态沿用独立的 `@vue/reactivity`，不使用 Vue 组件或 DOM 渲染器。HTTP、状态/聊天 WebSocket、收藏通知和返回键均通过宿主桥接；插件前端不读取 Token。前端固定使用已发布的 `@songloft/lynx-plugin-sdk@2.21.0`：HTTP 使用公开的 apiGet/apiPost/apiPut/apiDelete，状态与聊天连接复用 PluginSocket。

需要同时更新本次配套的服务端和 Lynx 客户端；旧宿主的 GET/POST 桥不具备完整编辑和实时连接能力，不能只更新插件包。HTML 回退需要服务端提供 `web-core/`。静态同步脚本会清理旧 Vue 产物，保留 builder 生成的入口；图标采用原生内联 SVG，避免字体在嵌套 frame 中失效。

验证命令、浏览器脚本及实际覆盖边界见 [Lynx 验证记录](docs/lynx-migration.md)。

## Description

智能音箱设备控制插件，内置洛雪音乐源（lxserver）在线搜索能力。本仓库**不附带任何第三方设备协议实现或账号体系**，使用者需自行负责接入合规性。

## 设备分组（多房间同步）

把多台音箱归入同一「设备分组」后，对组内**任一**音箱的播放控制会自动同步给组内**其他**成员，实现多房间同步播放。

实现方式很简单：**一个分组共用一套播放列表**——同一份队列、播放索引、播放模式、切歌定时器与随机序列，所有指令一次性下发给组内全部音箱。

- **覆盖操作**：播放歌单、暂停、继续、停止、上一首、下一首、切换播放模式、调节音量，以及单曲 URL 推送。
- **命令入口全覆盖**：无论从插件网页的播放控制按钮、对音箱说语音口令（如「下一首」「停止」「调大音量」），还是定时任务触发，都会带动全组。
- **切歌与自动续播都同步**：因为全组只有一份队列/一个定时器/一次随机选择，无论手动切歌还是一首播完自动续播，全组始终是同一首，**随机模式下也不会各放各的**。
- **容错**：组内某台离线/失败只记录告警，其余音箱照常播放；离线的音箱恢复后，下一条指令（含自动切歌）会自然覆盖到它。
- **成员互斥**：一台设备最多属于一个组。把设备加入新组时会自动从其它组移除。删除分组或移出成员后，相关设备恢复独立播放。

配置入口：插件页 → 设置 → 设备 → **设备分组**。点「新建分组」，填名称并勾选至少 2 台已启用管理的设备即可。分组信息持久化在插件本地存储，跨重启保留。

> 说明：智能音箱各自独立接收云端指令，不存在帧级同步协议，成员之间可能有轻微起播时差，属正常现象。

## 定时任务 - 法定节假日

定时任务的「每周」调度支持中国法定节假日感知,有三种模式:

- **忽略节假日**(默认):完全按勾选的星期触发,行为与节假日无关。
- **仅法定节假日触发**:今天必须是法定放假日(春节、国庆等)才触发,且星期也需在勾选范围内。适合「节假日早晨播音乐迎接好心情」这类场景。
- **真·工作日(跳过节假日,含调休补班)**:勾选「周一到周五」后开启此模式,则节假日跳过、调休补班的周末强制触发,符合「真正上班日的闹钟」语义。

节假日数据来自 [NateScarlet/holiday-cn](https://github.com/NateScarlet/holiday-cn)(MIT 协议),由 `npm run build`(或 `dev`)的 `prebuild` 钩子从 jsDelivr / GitHub raw 下载,覆盖当前年和下一年,并通过 esbuild 编入插件 bundle。运行时不需要网络访问。

注意事项:
- 国务院通常每年 11 月公布次年安排,在此之前下一年的节假日数据为空,此时会按「平常日」处理(不影响普通调度,但「仅法定节假日触发」模式将不会触发)。
- 每次发版会自动滚动到最新数据;长期未更新的插件版本可能缺失最新节假日,建议定期升级插件。
- 数据下载产物已 commit 入库,本地无网络也可构建。

## 在线搜索与内置洛雪音乐源（lxserver）

语音点歌在本地曲库未命中时，会按优先级发起在线搜索。插件**原生内置**洛雪音乐同步服务端（lxserver）客户端，搜索与直链解析都在插件进程内完成，不依赖额外中转插件；未命中或失败时自动回退到用户配置的外部 topone 搜索源（外部通道始终保留）。

### 配置

入口：插件页 → 设置 → 语音 → **内置洛雪音乐源（lxserver）**。

- **启用开关**：打开后参与在线搜索（默认关闭）。
- **服务地址**：如 `https://lx.example.com:9527`。
- **用户 Token**：可选（`lx_tk_...`）。插件会调用 `/api/user/auth/verify` 反查用户名，请求以 `x-user-name` + `x-user-token` 成对鉴权；留空则匿名，仅公开音源可用。
- **默认音质**：`320k`（默认）/ `flac` / `128k`；直链解析按 `flac → 320k → 128k` 阶梯降级。
- **搜索音源**：kw / kg / tx / wy / mg 并发搜索，按匹配度排序去重。
- **歌手在线歌曲**（默认关闭）：说话「播放歌手X」而本地曲库没有该歌手时，用 lxserver 拉取该歌手的多首热门歌整队播放，而不是只播搜到的第一首。**仅 tx / wy 音源支持歌手检索**，其余音源会跳过；解析不出直链时自动退回原来的「只播 top-1 单曲」行为。队列为临时列表（不入库），且只有前 2 首在起播前解析直链，其余在快播到时才解析，避免 10 首串行解析把首播推迟数秒。

兼容 lxserver 搜索响应的两种形态（旧版裸数组、v2.1.3+ 的 `{list,...}` 对象），字段映射与易变点兜底集中在 `src/lxserver/provider.ts` 适配层，服务端数据结构变化时只需改这一处。

### 两个测试入口

- **测试连接**（内置源卡片内）：只验证 lxserver 地址与 Token 是否可用（探活 + token 反查用户名）。
- **在线搜索测试**：走与语音点歌**完全相同**的搜索链路，只传关键词，不关心内部是内置还是外部源；输出会标明命中来源（`内置 lxserver` / `外部 topone`），可直接确认当前走的哪条路。

### 在线搜索通用设置

搜索优先级、歌曲匹配阈值、超时、**直链不入库直接播放**、自动追加歌单对内置与外部源**同时生效**。

- **直链不入库直接播放**（默认关闭）：开启后，带 http(s) 直链的结果不写入曲库，直接推给音箱——适合会过期的临时 CDN 直链，避免曲库堆积失效条目；此时「自动追加歌单」整组隐藏（追加歌单依赖入库后分配的歌曲 id，配置本身保留，关闭开关即恢复）。
  - 该模式下直链由插件当场向音源取，**不经过宿主的解析回调**、也不查库；只有源格式音箱解不了（webm/opus/flac/m4a 等）时才借宿主的 `/api/v1/proxy/transcode` 实时转 mp3，那条链接只是转码通道。
- 关闭时，**命中以「引用」入库（解析型音源）**：库里只存「怎么取到这首歌」，不存直链，播放时由宿主回调本插件的 `POST /api/music/url` 现解析。因此曲库条目不会因签名过期而失效，可收藏、可重播，同一首歌也因 `dedup_key` 只占一行；首次播放多一次解析往返（约 0.3~1s），之后宿主会落播放缓存。插件对外暴露的音源标识即 `plugin.json` 的 `entryPath`。
  - 内置 lxserver：引用记的是`平台 + 曲目标识`，直接按 id 重取直链。
  - 外部 topone 源：外部源通常只有搜索接口、没有「按 id 取直链」，所以引用记的是**当时怎么搜到的**（源 id + 搜索关键词 + 曲名/歌手/时长提示），播放时用同样参数重搜一次。原源不在配置里或那次偶发失败时，按配置顺序用其它启用源兜底。

> 首期仅实现在线搜索与直链播放。歌词、歌单读取、AI 推荐、多用户/房间歌单绑定尚未实现，接口已预留。

## 作为搜索源接入 miot（供插件开发者）

miot 在本地曲库搜不到歌时,会调用用户配置的「外部搜索源」把歌找回来推给音箱。任何插件只要实现了搜索接口,就能把自己**登记为候选**,出现在 miot 配置页的搜索源下拉里供用户一键选用——不必再靠 miot 写死内置列表。

接入分两步:

### 1. 实现搜索接口 `/api/search/topone`

`POST`,请求/响应遵循 topone 规范(完整定义见 miot 配置页「外部搜索」区的**「接口规范」**对话框):

- 请求体 `{ keyword, hint?: { title, artist, duration }, quality? }`
- 成功响应 `{ code: 0, msg, data: { title, artist, album?, duration?, cover_url?, url?, plugin_entry_path?, source_data?, dedup_key?, lyric?, lyric_source? } }`
- 未命中 / 失败返回 `code != 0`、`data: null`;**超时 6 秒**

内置的 `ytdlp` / `bili` / `subsonic` 即此规范的参考实现。

### 2. 经插件间通信(`songloft.comm`)注册为候选

在你的 `plugin.json` 声明 `inter-plugin` 权限,并在 `onInit` 里向 miot 注册:

```ts
// 延迟 + 重试,规避与 miot 同时启动的竞态;
// miot 未安装 / 旧版 host 无 comm 时静默跳过,绝不阻塞自身功能。
function registerToMiot() {
  let attempts = 0;
  const tryRegister = async () => {
    attempts++;
    try {
      if (!songloft.comm || typeof songloft.comm.call !== 'function') return;
      await songloft.comm.call('miot', 'register-search-provider', {
        name: '我的音源',                  // 下拉显示名
        searchPath: '/api/search/topone',  // 你的搜索路由(默认即此,可省)
        icon: '',                          // 可选
      });
    } catch (e) {
      if (attempts < 5) setTimeout(tryRegister, 3000);
    }
  };
  setTimeout(tryRegister, 2000);
}
```

| action | 说明 |
|--------|------|
| `register-search-provider` | 注册 / 更新候选(幂等,按 entryPath 覆盖,每次 onInit 重复调用即可) |
| `unregister-search-provider` | 注销候选(可选,一般在 onDeinit 调用;payload 传空即可) |

要点:

- **不用传 entryPath**:miot 以宿主注入的**可信调用方身份**为准(`from`),插件无法把自己伪造成别的插件。
- **payload 字段**:`name`(显示名,缺省用 entryPath)、`searchPath`(默认 `/api/search/topone`)、`icon`(可选)。
- **纯增强、无副作用**:注册只是让你出现在候选下拉;是否启用由用户在配置页决定。miot 会通过宿主插件列表校验你的 `installed/active` 状态,你被卸载后会自动从列表消失。
- **向后兼容**:内置 `ytdlp/bili/subsonic` 也走这套注册流程,同时保留在 miot 的内置 fallback 列表中,兼容尚未接入的旧版本。
